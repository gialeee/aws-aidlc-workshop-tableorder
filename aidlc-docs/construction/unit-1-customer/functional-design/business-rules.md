# Business Rules - Unit 1: Customer

## BR-C1: 테이블 인증

### BR-C1.1: 로그인 입력 검증
- store_code: 필수, 문자열, 1~50자
- table_number: 필수, 정수, > 0
- password: 필수, 문자열, 1~100자

### BR-C1.2: 인증 실패 처리
- 매장 미존재 → 404 "매장을 찾을 수 없습니다"
- 테이블 미존재 → 404 "테이블을 찾을 수 없습니다"
- 비밀번호 불일치 → 401 "비밀번호가 올바르지 않습니다"

### BR-C1.3: 세션 관리
- 테이블당 활성 세션 최대 1개
- 이미 활성 세션이 있으면 기존 세션 재사용
- 세션 ID는 모든 API 요청의 인증 수단 (헤더: X-Session-Id)

### BR-C1.4: 자동 로그인 (Frontend)
- LocalStorage 키: `tableOrder_credentials`
- 저장 형식: `{ store_code, table_number, password }`
- 앱 로드 시 자동 로그인 시도
- 실패 시 저장된 credentials 삭제

## BR-C2: 메뉴 조회

### BR-C2.1: 메뉴 필터링
- is_available=True인 메뉴만 고객에게 노출
- 카테고리별 필터링 지원 (category_id 파라미터)
- 전체 보기 시 category_id 생략

### BR-C2.2: 정렬 규칙
- 카테고리: sort_order ASC → id ASC
- 메뉴: sort_order ASC → id ASC

### BR-C2.3: 세션 인증 필요
- 메뉴 조회 API는 유효한 session_id 필요
- 비활성 세션 → 401

---

## BR-C3: 장바구니

### BR-C3.1: 수량 제한
- 단일 메뉴 최대 수량: 99
- 최소 수량: 1 (0이 되면 자동 삭제)

### BR-C3.2: 가격 계산
- 소계 = 단가 × 수량
- 총액 = 모든 소계의 합
- 모든 금액은 정수 (원 단위)

### BR-C3.3: 데이터 유지
- SessionStorage 사용 (탭 닫으면 초기화)
- 페이지 새로고침 시 복원
- 주문 성공 시 자동 비우기

---

## BR-C4: 주문 생성

### BR-C4.1: 주문 전 검증
- 장바구니가 비어있으면 주문 불가
- 세션이 활성 상태여야 함
- 모든 메뉴가 is_available=True여야 함

### BR-C4.2: 주문 데이터 스냅샷
- OrderItem에 주문 시점의 menu_name, unit_price 저장
- 이후 메뉴 가격/이름 변경과 무관하게 주문 기록 유지

### BR-C4.3: 주문 성공 후 동작 (Frontend)
- 장바구니 자동 비우기
- 토스트 알림으로 주문 번호 표시
- 즉시 메뉴 화면으로 리다이렉트

### BR-C4.4: 주문 실패 처리
- 장바구니 유지 (비우지 않음)
- 에러 메시지 토스트 표시
- 재시도 가능

---

## BR-C5: 주문 내역 조회

### BR-C5.1: 조회 범위
- 현재 활성 세션의 주문만 표시
- 이전 세션(이용 완료된) 주문은 미표시

### BR-C5.2: 정렬
- 주문 시각 기준 최신순 (created_at DESC)

### BR-C5.3: 표시 정보
- 주문 번호, 주문 시각, 상태 (대기중/준비중/완료)
- 주문 항목: 메뉴명, 수량, 단가, 소계
- 주문 총액
