# 테이블오더 서비스 요구사항 문서

## Intent Analysis

### User Request
테이블오더 서비스 구축 - 고객이 테이블에서 직접 주문하고, 매장 운영자가 실시간으로 주문을 관리할 수 있는 디지털 주문 시스템

### Request Classification
- **Request Type**: New Project (신규 프로젝트)
- **Request Clarity**: Clear (상세한 요구사항 문서 제공)
- **Initial Scope**: System-wide (전체 시스템 구축)
- **Initial Complexity**: Complex (다중 인터페이스, 실시간 통신, 세션 관리)

---

## 1. 프로젝트 개요

### 1.1 서비스 비전
디지털 주문 시스템을 통해 고객에게는 편리한 주문 경험을, 매장 운영자에게는 효율적인 운영 환경을 제공하는 차세대 테이블오더 플랫폼

### 1.2 핵심 가치 제안

**고객 관점**:
- 대기 시간 없는 즉시 주문
- 직관적이고 사용하기 쉬운 인터페이스

**매장 운영자 관점**:
- 인건비 절감 및 운영 효율성 증대
- 실시간 주문 관리 및 모니터링

**시장 차별화**:
- 다양한 업종에 적용 가능한 유연한 구조
- 직관적인 관리자 도구

## 2. 기능 요구사항 (Functional Requirements)

### 2.1 고객용 기능

#### 2.1.1 테이블 태블릿 자동 로그인 및 세션 관리
- **초기 설정 (관리자가 1회 수행)**:
  - 매장 식별자 입력
  - 테이블 번호 입력
  - 테이블 비밀번호 입력 (bcrypt 해싱)
  - 로그인 정보 LocalStorage에 저장
- **자동 로그인**:
  - 저장된 정보로 자동 로그인
  - 16시간 세션 유지
  - 테이블 세션 ID는 서버에서 UUID로 생성

#### 2.1.2 메뉴 조회 및 탐색
- 메뉴 화면이 기본 화면으로 표시
- 카테고리별 메뉴 분류 및 표시
- 메뉴 상세 정보 표시:
  - 메뉴명
  - 가격
  - 메뉴 설명
  - 메뉴 이미지 (URL 기반, 외부 호스팅)
- 카드 형태의 메뉴 레이아웃
- 터치 친화적인 버튼 크기 (최소 44x44px)

#### 2.1.3 장바구니 관리
- 메뉴 추가/삭제
- 수량 조절 (증가/감소)
- 총 금액 실시간 계산
- 장바구니 비우기
- SessionStorage에 저장 (브라우저 세션 동안 유지)

#### 2.1.4 주문 생성
- 주문 내역 최종 확인
- 주문 확정 버튼
- **주문 성공 플로우**:
  - 주문 번호 표시
  - 장바구니 자동 비우기
  - 메뉴 화면으로 자동 리다이렉트
- 주문 실패 시 에러 메시지 표시 및 장바구니 유지
- **주문 정보 포함 항목**:
  - 매장 식별 정보
  - 테이블 식별 정보
  - 주문 메뉴 목록 (메뉴명, 수량, 단가)
  - 총 주문 금액
  - 세션 ID
  - 주문 상태 (초기값: "대기중")

#### 2.1.5 주문 내역 조회
- 주문 시간 순 정렬 (최신순)
- 주문별 상세 정보 표시:
  - 주문 번호
  - 주문 시각
  - 주문 메뉴 및 수량
  - 주문 금액
  - 주문 상태 (대기중/준비중/완료)
- **현재 테이블 세션 주문만 표시** (이전 식사 세션 제외)
- 매장 이용 완료 처리된 주문은 제외

### 2.2 관리자용 기능

#### 2.2.1 매장 인증
- 매장 식별자 입력
- 사용자명 및 비밀번호 입력 (bcrypt 해싱)
- **세션 관리**:
  - 16시간 세션 유지
  - JWT 토큰 기반 인증
  - 토큰은 LocalStorage에 저장
  - 브라우저 새로고침 시 세션 유지
  - 16시간 후 자동 로그아웃

#### 2.2.2 실시간 주문 모니터링
- **주문 목록 실시간 업데이트**:
  - Server-Sent Events (SSE) 사용
  - 단순 SSE 연결 (재연결 로직 포함)
  - 2초 이내 주문 표시
- **그리드/대시보드 레이아웃**:
  - 테이블별 카드 형태 표시
  - 각 테이블 카드에 총 주문액 표시
  - 최신 주문 n개 미리보기
- **주문별 상세 정보**:
  - 테이블 번호
  - 주문 번호
  - 주문 시각
  - 주문 메뉴 및 수량 (축약)
  - 총 금액
  - 주문 상태
- **주문 카드 클릭 시**: 전체 메뉴 목록 상세 보기
- **주문 상태 변경**: 관리자가 수동으로 변경 (대기중/준비중/완료)
- 신규 주문 시각적 강조 (색상 변경, 애니메이션)

#### 2.2.3 테이블 관리

**1. 테이블 태블릿 초기 설정**:
- 테이블 번호 및 테이블 비밀번호 설정
- 16시간 세션 생성
- 설정 정보 저장 및 자동 로그인 활성화

**2. 주문 삭제 (직권 수정)**:
- 특정 주문 삭제 버튼
- 확인 팝업 표시
- 주문 즉시 삭제 (데이터베이스 트랜잭션 사용)
- 테이블 총 주문액 재계산
- 성공/실패 피드백

**3. 테이블 세션 처리**:
- 테이블 세션 시작 및 종료 관리
- 확인 팝업 표시
- 테이블 세션 종료(이용 완료) 시:
  - 해당 세션의 주문 내역을 과거 이력으로 이동
  - 테이블 현재 주문 목록 및 총 주문액 0으로 리셋
- 새 고객이 이전 주문 내역 없이 시작 가능
- 성공/실패 피드백

**4. 과거 주문 내역 조회**:
- "과거 내역" 버튼
- 테이블별 과거 주문 목록 표시 (시간 역순)
- 각 주문 정보: 주문 번호, 시각, 메뉴 목록, 총 금액, 매장 이용 완료 시각
- 날짜 필터링 기능
- 데이터 보관 기간: 최근 1년
- "닫기" 버튼으로 대시보드 복귀

#### 2.2.4 메뉴 관리
- 메뉴 조회 (카테고리별)
- 메뉴 등록:
  - 메뉴명 (필수)
  - 가격 (필수)
  - 설명
  - 카테고리 (필수)
  - 이미지 URL
- 메뉴 수정
- 메뉴 삭제
- 메뉴 노출 순서 조정

## 3. 비기능 요구사항 (Non-Functional Requirements)

### 3.1 기술 스택

#### 3.1.1 프론트엔드
- **Framework**: React (SPA - Single Page Application)
- **고객용 및 관리자용 동일한 기술 스택 사용**
- **코드 품질**: ESLint + Prettier

#### 3.1.2 백엔드
- **Framework**: Python FastAPI
- **코드 품질**: Pylint

#### 3.1.3 데이터베이스
- **Type**: Relational Database
- **DBMS**: PostgreSQL
- **동시성 제어**: 데이터베이스 트랜잭션 사용

#### 3.1.4 실시간 통신
- **Protocol**: Server-Sent Events (SSE)
- **구현**: 단순 SSE 연결 (재연결 로직 포함)

### 3.2 보안

#### 3.2.1 인증 및 세션
- **관리자 인증**: JWT 토큰 기반
- **세션 유지**: 16시간
- **비밀번호 저장**: bcrypt 해싱
- **토큰 저장**: LocalStorage (관리자), LocalStorage (테이블 로그인)

#### 3.2.2 데이터 보호
- 테이블 비밀번호 bcrypt 해싱
- 관리자 비밀번호 bcrypt 해싱

### 3.3 성능
- 실시간 주문 표시: 2초 이내
- 주문 생성 응답 시간: 1초 이내 목표

### 3.4 데이터 관리

#### 3.4.1 데이터 저장
- **장바구니**: SessionStorage (브라우저 세션 동안 유지)
- **테이블 로그인 정보**: LocalStorage (영구 보존)
- **관리자 JWT 토큰**: LocalStorage (영구 보존)

#### 3.4.2 데이터 보관
- **과거 주문 내역**: 최근 1년
- **현재 주문**: 세션 종료 시 과거 이력으로 이동

### 3.5 배포 및 운영

#### 3.5.1 배포 환경
- **컨테이너화**: Docker 컨테이너
- **배포 방식**: 프론트엔드와 백엔드 모두 컨테이너로 배포

#### 3.5.2 환경 설정
- **.env 파일** 사용

#### 3.5.3 로깅 및 모니터링
- **로깅**: 파일 기반 로깅 (Python logging 모듈 사용)
- **에러 처리**: 기본 에러 핸들링

### 3.6 테스트
- **테스트 전략**: Unit tests만
- **테스트 범위**: 핵심 비즈니스 로직

### 3.7 사용성 (Usability)
- 터치 친화적인 UI (최소 버튼 크기 44x44px)
- 직관적인 네비게이션
- 명확한 시각적 피드백

## 5. 데이터 모델 개요

### 5.1 주요 엔티티
- **Store (매장)**: 매장 정보
- **Table (테이블)**: 테이블 정보 및 비밀번호
- **Menu (메뉴)**: 메뉴 정보
- **Category (카테고리)**: 메뉴 카테고리
- **Order (주문)**: 주문 정보
- **OrderItem (주문 항목)**: 주문별 메뉴 항목
- **TableSession (테이블 세션)**: 테이블 이용 세션
- **Admin (관리자)**: 관리자 계정

### 5.2 주요 관계
- Store 1:N Table
- Store 1:N Menu
- Store 1:N Category
- Store 1:N Admin
- Table 1:N TableSession
- TableSession 1:N Order
- Order 1:N OrderItem
- Menu 1:N OrderItem
- Category 1:N Menu

- **로그인 화면**: 매장 인증

## 7. API 요구사항

### 7.1 고객용 API
- `POST /api/table/login` - 테이블 로그인
- `GET /api/menus` - 메뉴 목록 조회
- `GET /api/menus/{id}` - 메뉴 상세 조회
- `POST /api/orders` - 주문 생성
- `GET /api/orders` - 주문 내역 조회 (현재 세션)

### 7.2 관리자용 API
- `POST /api/admin/login` - 관리자 로그인
- `GET /api/admin/orders/stream` - 실시간 주문 스트림 (SSE)
- `GET /api/admin/orders` - 주문 목록 조회
- `PUT /api/admin/orders/{id}/status` - 주문 상태 변경
- `DELETE /api/admin/orders/{id}` - 주문 삭제
- `POST /api/admin/tables/{id}/session/end` - 테이블 세션 종료
- `GET /api/admin/tables/{id}/history` - 테이블 과거 주문 내역
- `GET /api/admin/menus` - 메뉴 목록 조회
- `POST /api/admin/menus` - 메뉴 생성
- `PUT /api/admin/menus/{id}` - 메뉴 수정
- `DELETE /api/admin/menus/{id}` - 메뉴 삭제

## 8. 용어 정의

- **MVP**: Minimum Viable Product (최소 기능 제품)
- **API**: Application Programming Interface
- **UI/UX**: User Interface / User Experience
- **SSE**: Server-Sent Events (서버에서 클라이언트로 단방향 실시간 통신)
- **JWT**: JSON Web Token (인증 토큰)
- **SPA**: Single Page Application
- **테이블 세션**: 특정 테이블에 고객이 앉아서 첫 주문 시작 후부터 해당 테이블 이용 완료 처리까지의 시간. 세션 종료 후 다른 고객의 첫 주문 시작 시, 새로운 세션 시작.

## 9. 성공 기준

### 9.1 기능적 성공 기준

**고객용**:
- 테이블 태블릿에서 자동 로그인이 정상 동작함
- 카테고리별 메뉴를 조회하고 상세 정보를 확인할 수 있음
- 장바구니에 메뉴를 추가/삭제/수량 변경할 수 있음
- 장바구니의 내용을 주문으로 생성할 수 있음
- 주문 성공 시 장바구니가 비워지고 메뉴 화면으로 리다이렉트됨
- 현재 세션의 주문 내역과 상태를 확인할 수 있음

**관리자용**:
- 매장 인증 후 관리자 대시보드에 접근할 수 있음
- 실시간으로 신규 주문이 대시보드에 표시됨 (SSE)
- 주문 상태를 수동으로 변경할 수 있음 (대기중/준비중/완료)
- 특정 주문을 삭제할 수 있음
- 테이블 세션을 종료(이용 완료)하고 주문 내역이 과거 이력으로 이동됨
- 과거 주문 내역을 날짜별로 조회할 수 있음
- 메뉴를 등록/수정/삭제할 수 있음

### 9.2 비기능적 성공 기준
- 주문이 2초 이내에 관리자 화면에 표시됨
- 페이지 새로고침 후에도 장바구니(SessionStorage)와 로그인 상태(LocalStorage)가 유지됨
- 16시간 세션이 정상적으로 유지되고 만료 시 자동 로그아웃됨
- 동시 주문 시 데이터 일관성이 보장됨 (트랜잭션)
- 시스템이 안정적으로 동작함 (에러 없이)
- UI가 직관적이고 터치 친화적임

## 10. 제약사항 및 가정

### 10.1 제약사항
- 단일 매장만 지원 (멀티 테넌시 없음)
- 실제 결제 기능 없음
- 주방 시스템 연동 없음
- 이미지 업로드 기능 없음 (URL만 사용)

### 10.2 가정
- 테이블 태블릿은 항상 온라인 상태
- 관리자는 데스크톱 또는 태블릿에서 접근
- 네트워크 연결이 안정적임
- 이미지는 외부에서 호스팅됨
