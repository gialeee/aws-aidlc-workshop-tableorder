# User Stories

## 분류 방식: Feature-Based
## 세분화 수준: Fine (Task 수준)
## Acceptance Criteria: Checklist 형식
## 우선순위: P0 (Critical) / P1 (High) / P2 (Medium) / P3 (Low)

---

# Feature 1: 테이블 인증 (Table Authentication)

## US-1.1: 테이블 초기 설정
**As a** 관리자  
**I want to** 테이블 태블릿에 매장 식별자, 테이블 번호, 비밀번호를 설정할 수 있다  
**So that** 고객이 별도 로그인 없이 주문할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 매장 식별자 입력 필드가 존재한다
- [ ] 테이블 번호 입력 필드가 존재한다
- [ ] 테이블 비밀번호 입력 필드가 존재한다
- [ ] 설정 완료 시 로그인 정보가 LocalStorage에 저장된다
- [ ] 설정 완료 시 자동 로그인이 활성화된다

## US-1.2: 테이블 자동 로그인
**As a** 고객  
**I want to** 태블릿을 켜면 자동으로 로그인된다  
**So that** 별도 인증 절차 없이 바로 주문할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] LocalStorage에 저장된 정보로 자동 로그인 시도한다
- [ ] 로그인 성공 시 메뉴 화면으로 이동한다
- [ ] 로그인 실패 시 초기 설정 화면을 표시한다
- [ ] 16시간 세션이 유지된다

# Feature 2: 메뉴 조회 (Menu Browsing)

## US-2.1: 카테고리별 메뉴 목록 조회
**As a** 고객  
**I want to** 카테고리별로 분류된 메뉴 목록을 볼 수 있다  
**So that** 원하는 종류의 메뉴를 쉽게 찾을 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 메뉴 화면이 기본 화면으로 표시된다
- [ ] 카테고리 탭/버튼이 표시된다
- [ ] 카테고리 선택 시 해당 카테고리의 메뉴만 표시된다
- [ ] 카테고리 간 빠른 이동이 가능하다

## US-2.2: 메뉴 상세 정보 확인
**As a** 고객  
**I want to** 메뉴의 상세 정보(이름, 가격, 설명, 이미지)를 확인할 수 있다  
**So that** 주문 전에 메뉴에 대해 충분히 파악할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 메뉴명이 표시된다
- [ ] 가격이 표시된다
- [ ] 메뉴 설명이 표시된다
- [ ] 메뉴 이미지가 표시된다 (URL 기반)
- [ ] 카드 형태의 레이아웃으로 표시된다
- [ ] 터치 친화적인 버튼 크기 (최소 44x44px)

# Feature 3: 장바구니 관리 (Cart Management)

## US-3.1: 장바구니에 메뉴 추가
**As a** 고객  
**I want to** 원하는 메뉴를 장바구니에 추가할 수 있다  
**So that** 여러 메뉴를 모아서 한 번에 주문할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 메뉴 카드에서 추가 버튼을 누르면 장바구니에 담긴다
- [ ] 이미 담긴 메뉴를 다시 추가하면 수량이 증가한다
- [ ] 장바구니에 담긴 메뉴 수가 표시된다

## US-3.2: 장바구니 수량 변경
**As a** 고객  
**I want to** 장바구니에 담긴 메뉴의 수량을 변경할 수 있다  
**So that** 원하는 만큼 주문할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 수량 증가 버튼이 동작한다
- [ ] 수량 감소 버튼이 동작한다
- [ ] 수량이 0이 되면 해당 메뉴가 장바구니에서 삭제된다
- [ ] 수량 변경 시 총 금액이 실시간으로 재계산된다

## US-3.3: 장바구니에서 메뉴 삭제
**As a** 고객  
**I want to** 장바구니에서 특정 메뉴를 삭제할 수 있다  
**So that** 주문하지 않을 메뉴를 제거할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 삭제 버튼을 누르면 해당 메뉴가 장바구니에서 제거된다
- [ ] 삭제 후 총 금액이 재계산된다

## US-3.4: 장바구니 비우기
**As a** 고객  
**I want to** 장바구니를 한 번에 비울 수 있다  
**So that** 처음부터 다시 메뉴를 선택할 수 있다  
**Priority**: P1

**Acceptance Criteria**:
- [ ] 장바구니 비우기 버튼이 존재한다
- [ ] 비우기 실행 시 모든 메뉴가 제거된다
- [ ] 총 금액이 0으로 초기화된다

## US-3.5: 장바구니 총 금액 표시
**As a** 고객  
**I want to** 장바구니의 총 금액을 실시간으로 확인할 수 있다  
**So that** 주문 전에 총 비용을 파악할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 총 금액이 장바구니 화면에 표시된다
- [ ] 메뉴 추가/삭제/수량 변경 시 즉시 업데이트된다

## US-3.6: 장바구니 데이터 유지
**As a** 고객  
**I want to** 페이지를 새로고침해도 장바구니 내용이 유지된다  
**So that** 실수로 새로고침해도 다시 담을 필요가 없다  
**Priority**: P1

**Acceptance Criteria**:
- [ ] 장바구니 데이터가 SessionStorage에 저장된다
- [ ] 페이지 새로고침 시 장바구니가 복원된다
- [ ] 브라우저 탭을 닫으면 장바구니가 초기화된다

# Feature 4: 주문 생성 (Order Creation)

## US-4.1: 주문 내역 최종 확인
**As a** 고객  
**I want to** 주문 전에 장바구니 내용을 최종 확인할 수 있다  
**So that** 잘못된 주문을 방지할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 주문 확정 전 메뉴 목록, 수량, 단가, 총 금액이 표시된다
- [ ] 주문 확정 버튼이 존재한다

## US-4.2: 주문 확정
**As a** 고객  
**I want to** 장바구니의 내용을 주문으로 확정할 수 있다  
**So that** 매장에서 음식을 준비받을 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 주문 확정 버튼 클릭 시 서버에 주문이 전송된다
- [ ] 주문 정보에 매장 식별자, 테이블 번호, 메뉴 목록, 수량, 단가, 총 금액, 세션 ID가 포함된다
- [ ] 주문 성공 시 주문 번호가 표시된다
- [ ] 주문 성공 시 장바구니가 자동으로 비워진다
- [ ] 주문 성공 시 메뉴 화면으로 자동 리다이렉트된다
- [ ] 주문 실패 시 에러 메시지가 표시된다
- [ ] 주문 실패 시 장바구니가 유지된다

# Feature 5: 주문 내역 조회 (Order History - Customer)

## US-5.1: 주문 내역 조회
**As a** 고객  
**I want to** 현재 테이블 세션의 주문 내역과 상세 정보를 확인할 수 있다  
**So that** 이번 식사에서 무엇을 주문했는지 파악할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 현재 세션의 주문만 표시된다 (이전 세션 제외)
- [ ] 주문 시간 순으로 정렬된다
- [ ] 매장 이용 완료 처리된 주문은 표시되지 않는다
- [ ] 주문 번호가 표시된다
- [ ] 주문 시각이 표시된다
- [ ] 주문 메뉴 및 수량이 표시된다
- [ ] 주문 금액이 표시된다
- [ ] 주문 상태 (대기중/준비중/완료)가 표시된다

# Feature 6: 관리자 인증 (Admin Authentication)

## US-6.1: 관리자 로그인
**As a** 관리자  
**I want to** 매장 식별자, 사용자명, 비밀번호로 로그인할 수 있다  
**So that** 매장 관리 시스템에 접근할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 매장 식별자 입력 필드가 존재한다
- [ ] 사용자명 입력 필드가 존재한다
- [ ] 비밀번호 입력 필드가 존재한다
- [ ] 로그인 성공 시 JWT 토큰이 발급된다
- [ ] JWT 토큰이 LocalStorage에 저장된다
- [ ] 로그인 성공 시 대시보드로 이동한다
- [ ] 로그인 실패 시 에러 메시지가 표시된다

## US-6.2: 관리자 세션 유지
**As a** 관리자  
**I want to** 16시간 동안 세션이 유지된다  
**So that** 근무 중 반복 로그인 없이 사용할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 브라우저 새로고침 시 세션이 유지된다
- [ ] 16시간 후 자동 로그아웃된다
- [ ] 자동 로그아웃 시 로그인 화면으로 이동한다

# Feature 7: 실시간 주문 모니터링 (Real-time Order Monitoring)

## US-7.1: 테이블별 주문 대시보드 조회
**As a** 관리자  
**I want to** 테이블별 주문 현황을 그리드 형태로 한눈에 볼 수 있다  
**So that** 매장 전체 주문 상황을 빠르게 파악할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 테이블별 카드 형태로 표시된다
- [ ] 각 테이블 카드에 총 주문액이 표시된다
- [ ] 최신 주문 n개가 미리보기로 표시된다
- [ ] 그리드 레이아웃으로 배치된다

## US-7.2: 실시간 주문 업데이트 수신
**As a** 관리자  
**I want to** 신규 주문이 실시간으로 대시보드에 표시된다  
**So that** 주문을 놓치지 않고 즉시 확인할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] SSE (Server-Sent Events)로 실시간 업데이트를 수신한다
- [ ] 신규 주문이 2초 이내에 표시된다
- [ ] 연결 끊김 시 자동 재연결된다

## US-7.3: 신규 주문 시각적 강조
**As a** 관리자  
**I want to** 새로 들어온 주문이 시각적으로 강조된다  
**So that** 새 주문을 즉시 인지할 수 있다  
**Priority**: P1

**Acceptance Criteria**:
- [ ] 신규 주문에 색상 변경 또는 애니메이션이 적용된다
- [ ] 기존 주문과 시각적으로 구분된다

## US-7.4: 주문 상세 보기
**As a** 관리자  
**I want to** 주문 카드를 클릭하면 전체 메뉴 목록을 상세히 볼 수 있다  
**So that** 주문 내용을 정확히 확인할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 주문 카드 클릭 시 상세 정보가 표시된다
- [ ] 테이블 번호, 주문 번호, 주문 시각이 표시된다
- [ ] 전체 주문 메뉴 및 수량이 표시된다
- [ ] 총 금액이 표시된다
- [ ] 주문 상태가 표시된다

## US-7.5: 주문 상태 변경
**As a** 관리자  
**I want to** 주문 상태를 수동으로 변경할 수 있다 (대기중/준비중/완료)  
**So that** 주문 처리 진행 상황을 관리할 수 있다  
**Priority**: P0

**Acceptance Criteria**:
- [ ] 대기중 → 준비중 상태 변경이 가능하다
- [ ] 준비중 → 완료 상태 변경이 가능하다
- [ ] 상태 변경이 즉시 반영된다

**Acceptance Criteria**:

- [ ] 메뉴명, 가격, 카테고리가 표시된다

**Priority**: P0

**Acceptance Criteria**:
